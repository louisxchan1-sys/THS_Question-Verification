# 出卷流程
> 製作 THS 測考試卷（統一測驗、上／下學期考試、mock）及工作紙／習作／小測：問題紙、答題簿、評卷參考｜入口：`/make-paper`｜更新：2026-11-22（由「4. 測考試卷製作器」CLAUDE.md §2、§3、§6 遷入）

**規則正本**：`考評標準/出題總則.md`、`考評標準/MC_／DBQ_／LQ_出題規格.md`、`考評標準/評分準則撰寫標準.md`。本流程只講「怎樣做」，數字標準一律看正本。

## 一、指令優先次序

1. 使用者本次明確要求。
2. `考評標準/`（規則正本）及本資料夾流程。
3. `範本/` 的實際版面（只管**版面**，見 `DOCX版面規格.md`）。
4. `參考資料/`：課本資料（課文依據）、公開試（題型與難度基準，只用 2020–2026）、試題分析。
5. 舊輸出、Drive 封存資料。

## 二、出卷前必須確認

缺少以下任何一項即用 AskUserQuestion 追問，不可開始出題：

- 年級（中四／中五／中六）、學年及學期、考核形式（統測／考試／mock／工作紙）。
- 工作紙：卷首「考試名稱」寫「工作紙」（使用者可改為「習作」「小測」等），時限、總分照填；**題型及題數由使用者指定**。
- 考核範圍：章節或課題。使用者用**天行舊章號**（如「第 18–22 章」）時，先按 `參考資料/課本資料/00_章節對照表.md` 轉換為閎博章節，並在草稿規格表列明對照，請使用者確認。
- 試卷組成（試卷一／試卷二／兩卷）、各部題型、題數、分數、時限、考試日期、是否需要答題簿（預設需要）。
- 課文依據：預設閎博；使用者指定天行時照 `出題總則.md` §三處理。

只缺可由範本推斷的版面細節（如擬卷老師 CMC），按範本處理並在草稿列明假設。

## 三、讀取順序（不可只憑記憶出題）

1. `考評標準/出題總則.md` 及對應題型的出題規格。
2. 對應範本（`DOCX版面規格.md` §一）。
3. 課文：`參考資料/課本資料/00_章節對照表.md` → 按範圍讀相關檔案及小節（天行版只在指定時讀 `參考資料/課本資料_天行/`）。
4. 公開試：`參考資料/公開試/00_索引.md` → 本卷範疇的 2020–2026 真題（`01_`–`03_`）；2026 看卷式，2020–2025 看考點角度、問法及答對率（`04_選擇題答案/`）。
5. `參考資料/公開試/07_考生表現/`（2020–2025）：設計干擾項、校準難度時必讀本卷範疇相關年份。
6. 找錨題：`參考資料/公開試/THS_DSE歷屆試題分布(2012-2026).md` 及 `參考資料/試題分析/THS_DSE歷屆試題分布_熱門考點統計.md` 定位候選題號，**再讀原題**。
7. 需要趨勢、常考角度時：`參考資料/試題分析/`、`考評標準/課題出題頻率與TIER對照.md`、`考評標準/考生常見弱點與應試要訣.md`。
8. `進化/經驗庫.md`「現行待觀察模式」：出題時主動避開。

## 四、工作流程

1. **確認規格**（§二）。
2. **讀取資料**（§三）。
3. **草稿**：按 `草稿範本.md` 寫 `試卷輸出/{檔名}_試卷草稿.md`，包括規格表、問題紙全文、評卷參考全文、難度審核表及全卷統計、獨立作答紀錄、參考文件。
4. **草稿驗證**：交使用者前，先跑 `python3 scripts/ths_check.py 試卷輸出/{草稿}.md`，把所有 ✗ 改好、⚠ 改好或在全卷統計說明；再按 `驗證流程/驗證清單.md` A–E 自驗一次（F 可略），並把偏離目標的題目**先改好**；報告只附在草稿末段的「自驗摘要」（總評＋已修正項）。使用者要求時改用子代理執行，以免自己審自己。
5. **交使用者確認**草稿。
6. **修訂**：按使用者逐點修正更新草稿，不重寫未提及部分。使用者的每項糾正按 `進化/進化守則.md` §一記入經驗庫（類型「糾正」）。
7. **DOCX**：確認後（或使用者說「直接出 docx」）複製範本製作三份文件（問題紙、答題簿、評卷參考）→ 按 `DOCX版面規格.md` §六渲染驗證 → 對三份 DOCX 再跑一次 `scripts/ths_check.py`。
8. **交付前自查**：`交付前自查.md` 全部打勾。
9. **交付與回報**：見 §五。

## 五、輸出與交付

- 所有成品及草稿寫入 `試卷輸出/`（**不入 git**，屬校內試卷）。命名見 `DOCX版面規格.md` §五。
- 交付：以 `SendUserFile` 傳給使用者；使用者要求時，以 Google Drive 連接器上載到 Drive「4. 測考試卷製作器/3. output/」（不覆寫舊檔；被取代的舊版由使用者或在其同意下移入 `3. output/封存/`，不刪除）。
- 回報：一兩句說明完成內容、檔名、位置；列出假設及未能驗證的風險；最後列「參考文件」（只列真正讀取並作為依據的檔案）。
- 雲端環境會回收：交付後提醒使用者下載或同步到 Drive。
- 不輸出 JSON，除非使用者要求。
