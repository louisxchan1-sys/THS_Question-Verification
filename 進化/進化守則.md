# 進化守則（全自動模式）
> 本工具在每次驗證後自我修正規則的方法｜模式：全自動（AI 直接修訂並 commit，用戶事後檢視）｜建立：2026-11-22

## 零、原則

- **證據先行**：任何規則變更都必須能追溯至經驗庫條目（檔名＋題號）或用戶決定；沒有證據不改規則。
- **小步、可逆**：每次進化只改必要的最少文字；每次進化＝一個獨立 commit，可用 `git revert` 單獨撤回。
- **不可自改區**（只可在經驗庫寫「提案」，等用戶明確同意）：
  1. AGENTS.md「三條鐵律」
  2. A–F 六維名稱及定義範圍
  3. 總評等級（✅／⚠️／❌）及其判準
  4. 公開試現行制卷式（MC 30 題、DBQ 三選二、LQ 五選三 18+2）——只有考評局公布改制時才可改
- **不改參考資料**：`參考資料/` 是事實來源，只可由用戶更新；發現資料缺陷只記入經驗庫及 `範本對照表.md` 第四節。

## 一、記錄（每份驗證完成後必做）

把本次驗證中屬以下情況的觀察，追加到 `經驗庫.md`「條目」表：

| 類型 | 何時記錄 |
|:----|:----|
| 模式 | 問題可歸入既有模式 → 該模式「次數」+1，於「證據」補一例（檔名＋題號） |
| 新模式 | 出現現行規則未明文涵蓋的問題類型 |
| 陷阱 | 驗證過程本身的失誤或險些失誤（如錨題答對率引錯年份、讀 docx 漏表格） |
| 糾正 | 用戶推翻或修改 AI 的判斷 → 同時寫入 `決策紀錄.md` |
| 誤報 | 事後發現某條規則令 AI 誤判（規則過嚴／過寬） |

每條須有：日期、檔名、題號／位置、一句描述。寫不出證據的不記。

## 二、觸發與自動修訂

完成記錄後逐條檢查：

| 觸發條件 | 自動動作 |
|:----|:----|
| 同一模式累計 **≥3 份不同文件** | 把模式寫成明文規則，加入對應文件（見 §三） |
| 用戶糾正 **1 次** | 立即把決定寫入對應規則文件（決策紀錄保留原話） |
| 誤報 **≥2 次** | 收窄或加例外條件；若規則本身錯誤 → `git revert` 該規則的進化 commit |
| 陷阱 **≥2 次** | 加入 AGENTS.md「已知陷阱」 |
| 公開試／考生表現有新年度資料 | 只更新 `考評標準/範本對照表.md`（沿用原維護規則） |

觸發屬不可自改區 → 只寫「提案」欄，不改文件。

## 三、修改到哪裡

| 問題性質 | 目標文件 |
|:----|:----|
| 檢查項目缺漏 | `驗證流程/驗證清單.md` 對應維度加一個 `- [ ]` 項 |
| 題型規格細節 | `考評標準/MC_／DBQ_／LQ_出題規格.md` |
| 答案／評分寫法 | `考評標準/評分準則撰寫標準.md` |
| 驗證過程的陷阱 | `AGENTS.md`「已知陷阱」 |
| 報告寫法 | `驗證流程/驗證報告範本.md` |

修改後必做：
1. 更新該文件檔頭「更新：YYYY-MM-DD」。
2. 同步核對 AGENTS.md／驗證清單／驗證報告範本三者的 A–F 名稱與總評等級一致（原維護規則）。
3. 在 `CHANGELOG.md` 頂部加一條：日期｜文件§節｜改了甚麼｜觸發證據（經驗庫條目編號）。
4. 經驗庫對應條目「狀態」改為「已落實→CL-編號」。
5. 獨立 commit：`進化: <一句摘要>（經驗庫 #編號）`，push 到工作分支。

## 四、健康檢查（每 10 份驗證或每次 `/evolve`）

- **防膨脹**：已落實超過 3 個月且之後未再出現的條目，移到經驗庫「歸檔」節，只留一行。
- **防重複**：新規則與現有檢查項意思重疊 → 合併，不並存。
- **防漂移**：抽一份最近報告，用現行清單重走 E 維；如判級與報告不同 ≥2 題，記一條「陷阱」。
- **規則上限**：驗證清單每維最多 12 項；超出時先合併再新增。

## 五、用戶如何檢視／撤回

- 看變更：`進化/CHANGELOG.md`，或 `git log --grep "^進化:"`
- 撤回某次進化：`git revert <commit>`，並在決策紀錄寫明原因（AI 之後不得再自動加回同一規則）。
